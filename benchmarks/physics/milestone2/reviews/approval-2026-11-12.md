# Technical review decision: PV-TF1 draft 3 (received 12 Nov 2026)

Filed as received, in substance. The changes it required are recorded in `../spec-proposed/PV-TF1.json`
`definitionRevisions` (draft 3a) and in `../REGISTRATION.md`, Revision 3.

**Decision:** PV-TF1 draft 3 is approved to proceed.

- The zero-offset end-depth equivalence is accepted as sufficient for the full-conduit exclusion guard **in this
  specific registered geometry** (closes resolution-I1, Unresolved 1).
- New SWMM getters are not required.

**Final documentation clarifications required:**
1. Explicitly confirm that the node guard checks both endpoint nodes of every conduit segment, including the outfall
   endpoint.
2. State that zero offsets and a horizontal pipe are hard validity conditions. Any deviation invalidates the
   experiment.
3. Clarify that LINK_DEPTH is a recorded midpoint observation, not an independent measurement of the full conduit depth
   profile.
4. Document that the conduit WSE calculation uses the horizontal, zero-offset invert assumption.

**Constraints:**
- Do not change any acceptance criteria, hypotheses, geometry or boundary conditions.
- After the clarifications, proceed through the existing registration and hashing process, then run PV-TF1 as the
  first PVM2 experiment, and nothing else.
- Preserve all raw per-step output and the registered experiment configuration.
- Do not begin PV-RV1 or any other PVM2 experiment until PV-TF1's results have been reviewed.
- This is authorisation to register and run PV-TF1 only. It is not authorisation to modify production code or to
  proceed to subsequent experiments.

**Return:** the registered identity and hashes; the exact run configuration; the full-conduit guard results; the
rest-equilibrium results; the mass-balance and water-level results; any invalidation or insufficient-reference-data
conditions; the raw artifact locations.

## Response to clarification 1 (recorded, not a change to the decision)

In the registered geometry **no conduit segment has an outfall endpoint.** The conduit chain runs T1 → (J1 … J(N−1)) →
T2, and both terminal endpoints are storage nodes. The outfall `OUT` is joined only to the sealing weir W0 (T2 → OUT).
The guard is therefore stated as: both endpoints of every segment, read from the API at run time (LINK_NODE1,
LINK_NODE2), plus `OUT`, so that every node including the outfall is checked, and an outfall endpoint, had there been
one, would be checked like any other.
